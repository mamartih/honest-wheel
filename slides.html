The AI can only say no

An LLM is wired as a veto-only gate. It can block a trade the deterministic rules already approved. It can never authorise, size, or pick a strike.

ModelQwen2.5-7B-Instruct on Featherless AI · one call per surviving candidate · temperature 0
PositionLast gate. Consulted only about candidates that survived every deterministic check, so it can never rescue a rejected trade
Failure modeFails open. No key, timeout or unparseable answer → the deterministic decision stands. An LLM outage must not become a trading halt
Record"advisor": {"consulted": true, "veto": false}
Every cycle logs whether the advisor ran, veto or not. Silence on a fail-open would make “the advisor approved” and “the advisor never ran” look identical — and this page unfalsifiable.

What went wrong, published

Two failures worth more than the P&L. Both are in the repo, with the tests that now catch them.

  • The broker rejected an order our own gate had approved. 403 — required 74,194.01, available 25,935.98. The CAPITAL gate compared against the marginable equity figure; a cash-secured put draws on the non-marginable balance. The gate was right — it was handed the wrong magnitude.
  • And that is why a green suite never caught it: three CLI test doubles returned an account object with no such field. The code asked for something the fixtures had decided did not exist. Fixing it turned seven passing tests red.
  • Earlier: the liquidity gate measured the size of the last trade and called it daily volume. A contract traded 4,000 times and one traded once both reported “1”.
THE POINT   A green test suite does not say the code is right. It says the code does what the test asked — and if the test invents the world, the code answers an invented world. The broker does not have that problem.
